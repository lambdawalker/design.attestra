# ID capture architecture

**Status:** Proposed application integration for [go.attestra.aws.auth](https://github.com/lambdawalker/go.attestra.aws.auth), which currently has no ID evidence storage or provider workflow. The [identity verification architecture](../../../verification/identity/architecture.md) governs downstream reports and policy; capture and review are only the onboarding entry point.

1. After authenticated start, hand camera/document capture to the chosen plugin. Treat cancellation, permission denial, retake, and plugin errors as recoverable capture outcomes. Skip leaves the identity check `not_started` without changing the confirmed-email or passkey status.
2. Receive plugin outputs through a narrow adapter: evidence assets, capture metadata, and extracted fields. Validate the output and show extracted data for review. Preserve source values and user corrections separately; do not silently replace the original extraction.
3. On submission, create a versioned evidence record bound to the authenticated Cognito `sub`, store private assets, and return a stable submission ID. Retries must reconcile that ID and avoid duplicate provider requests. A new capture creates a new evidence version; earlier decisions remain attributable to their versions.
4. Run the automatic report (`autoReport`) and external provider (`thirdParty`) as separate status tracks, each with `not_started`, `pending`, `approved`, `rejected`, `inconclusive`, or `error`. Only the policy combining current applicable results can produce the user-facing identity decision. Do not equate OCR success, upload success, or one provider response with final approval.
5. Make status available after app restart and from the dashboard. Authenticate provider callbacks and deduplicate their event IDs; stale responses cannot overwrite a newer evidence version. Long-running checks resolve to a pending view and later status retrieval instead of holding the loading screen indefinitely.

Keep app-owned verification state in the application store keyed by `sub`; do not overload Cognito email/passkey attributes with document decisions. The capture plugin, external identity provider, legal consent text, retention period, deletion requirements, accepted document types, and retry/appeal policy remain product decisions before production. Minimize exposure of raw images and extracted data to clients, logs, and analytics.
