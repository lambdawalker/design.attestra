# Email confirmation AWS strategy

**Implementation:** [go.attestra.aws.auth](https://github.com/lambdawalker/go.attestra.aws.auth) contains the Go Lambda handlers and [Pulumi stack](https://github.com/lambdawalker/go.attestra.aws.auth/tree/main/infra) for this subfeature. Deployment, SES verification, client link routing, and a live Cognito integration check remain operational steps.

1. **Transaction store:** The Pulumi stack provisions DynamoDB for pending proofs, conditional state transitions, hourly email/source budgets, and single-use session grants. Each transaction binds request ID, email, A challenge, B hash, keyed C digest, generation, expiry, and attempt counters. TTL cleans up later; the API checks expiration before claims.
2. **API Lambda:** `POST /signup` gives a generic request ID, `POST /resend` rotates B/C without changing A, and `POST /confirm` requires B plus exactly one valid A or C. Only the winner of the conditional claim can create a Cognito user or request tokens. Manual C allows five wrong attempts per generation and an account budget across resends. A failed downstream session exchange routes to email OTP recovery, not confirmation replay.
3. **Email:** An application-controlled SES send contains an HTTPS link with B/request ID and separately displayed C. A and C do not appear in the URL or API response. The Pulumi stack provisions a SES domain identity and DKIM tokens; publish DNS records, verify the identity, and complete SES sending readiness before deployment to real users.
4. **Cognito session:** The API creates a passwordless, email-verified account only after application proof validation, with invitation email suppressed. Cognito's custom-challenge triggers verify a short-lived single-use server grant before issuing access/ID/refresh tokens. Public Cognito signup is disabled; existing confirmed accounts do not gain a signup shortcut. Check the complete handoff against an actual Cognito user pool and verify that a failed grant cannot issue tokens.
5. **Operations:** Scope API and trigger roles to their table, Cognito pool, and SES identity. Keep the keyed digest secret in encrypted Pulumi configuration and limit access to Lambda environment variables. Redact B, C, full verification URLs, tokens, and email content in logs. Monitor delivery failures, exhausted attempts, conditional conflicts, expired transactions, and recovery.

Run `go test ./...`, `go vet ./...`, and the Pulumi stack build as described in the [repository README](https://github.com/lambdawalker/go.attestra.aws.auth/blob/main/README.md). The `GET /verify-email` screen is hosted by the client application, never by this API, and has no server-side confirmation side effect.

AWS references: [DynamoDB conditional writes](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Expressions.ConditionExpressions.html), [SES verified identities](https://docs.aws.amazon.com/ses/latest/dg/verify-addresses-and-domains.html), [admin-created passwordless users](https://docs.aws.amazon.com/cognito-user-identity-pools/latest/APIReference/API_AdminCreateUser.html), and [Cognito custom authentication](https://docs.aws.amazon.com/cognito/latest/developerguide/user-pool-lambda-challenge.html).
