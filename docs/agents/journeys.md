# Journeys and failure recovery

Start at [onboarding](../../auth/onboarding/README.md). [Email confirmation](../../auth/onboarding/email-confirmation/flow.md) uses local proof A plus emailed B, or B plus separately displayed manual code C. A link fetch must not confirm an account. Generic signup acceptance does not prove delivery. Resend invalidates old material under server budgets. A lost successful confirmation response goes to sign-in recovery, not proof replay.

[Passkey creation](../../auth/onboarding/passkey-creation/flow.md) begins only with an authenticated session. The platform owns the credential picker/private key. Cancellation and unsupported devices retain email sign-in as the fallback. [Login](../../auth/login/architecture.md) and [resume](../../auth/onboarding/resume.md) are separate from initial confirmation.

[Capture](../../auth/onboarding/id-capture/flow.md) uploads photos to private S3 and freezes exact object versions for file checks. In the live Android flow, the grayscale front can start OCR before the back is captured when the backend advertises stitched pair support. A stitched color pair is uploaded for evidence while photo review stays open. Confirmation opens the matching result or shows loading. A retake invalidates older worker results and starts a replacement pair within the same capture. The client matches the capture ID and image revision before showing the result.

[Parsing and review](../../auth/onboarding/id-parsing/flow.md) uses the extraction stored on the capture record. Pending extraction shows loading, and failed extraction opens manual entry. A server-confirmed save opens Details saved, which completes the document-data step.

[ID validation](../../verification/id-validation/architecture.md) remains a separate deferred feature. A “details saved” or “capture ready” screen must never imply an identity-approved outcome. [Address verification](../../verification/address/architecture.md) has separate policy/provider decisions.

Implementation integration: [backend HTTP guide](https://raw.githubusercontent.com/lambdawalker/go.appexfission.aws.card-capture/main/docs/agents/index.md), [Android capture guide](https://raw.githubusercontent.com/lambdawalker/android.attestra.auth/main/docs/identity-capture.md), and [capture HTTP contract](https://raw.githubusercontent.com/lambdawalker/android.attestra.auth/main/docs/identity/http-contract.md). These guides change independently; consult the evidence ledger before claiming compatibility.

The capture worker implements [asynchronous field extraction and review](../../auth/onboarding/id-parsing/flow.md). A failed extraction offers manual entry. The parsing diagram describes the system design; the live API exposes extraction within the capture record. For deployed diagnostics, compare Android's observed wait with the matching backend invocation.
